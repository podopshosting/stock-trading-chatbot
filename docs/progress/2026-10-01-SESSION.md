## Two defects that aborted cycles, fixed during the session

Both were found by watching the live path, and neither could have been
caught by the component tests as they stood.

1. **13:37 — `KeyError: 'conditions'`.** The first cycle's
   `record_cycle()` created the health item with only a `streak`
   attribute; the next cycle's read indexed `conditions`, which was not
   there. Every subsequent cycle aborted. A record created by one write
   path was unreadable by another.
2. **13:38 — `'>' not supported between 'method' and 'float'`.** The
   handler returned `Provenance.age_seconds` — a bound method — instead
   of calling it, and the Risk Governor compared it to a float. The same
   fix also derives dollar volume from session volume: the provider's
   `Quote` has no `dollar_volume` field, so every candidate would have
   been refused for unknown liquidity.

Each has a regression test that fails without its fix, written against
the real `Quote`/`Provenance` types rather than the floats the old fakes
supplied.

**Cohort 1 is void.** Before 13:39:39 the agent could not have traded.
Evidence from before and after that deploy must not be pooled.

## Evidence integrity: what the session taught about the record itself

The stored tally named code SHA `8674df7` for all of today's cycles while
14 of the first 15 actually ran `66989c4`. The cohort key excludes
`code_sha` by design — a documentation commit must not reset the evidence
— so a redeploy inside a session was invisible.

Now recorded and enforced:

- `SessionTally.code_shas` holds every SHA a session ran under. A session
  spanning more than one is **VOID**: named in the readiness report and
  excluded from the session count, because its totals describe no single
  program.
- Each cycle records the **data quality** it traded on, and each session
  carries an evidence class:
  `REAL_TIME_STRATEGY_EVIDENCE` / `OPERATIONAL_VALIDATION_ONLY` / `VOID`.
- `demonstrated_edge`, `stops_hold` and `strength_is_predictive` refuse
  to be met by anything that is not real-time, single-runtime evidence,
  and say so in the gate detail. Unrecorded reads as UNKNOWN, never as
  real-time.

Today's session will classify as **OPERATIONAL_VALIDATION_ONLY**: the
cycle Lambda predates the recording, so its data quality is UNKNOWN,
which fails closed. The recording ships with the next cycle deploy —
deliberately **after** the close, so the session is not fragmented
further.

Today's tally cannot be retro-flagged as redeploy-spanning, because
`code_shas` did not exist when it was written. That is stated here rather
than corrected by hand: editing an evidence record to say what we know is
how evidence stops being evidence.

## The finding that matters most: the data is 15 minutes old

The agent trades on Alpaca's `delayed_sip` feed. Verified from its own
output at 14:39 UTC: `data_quality.is_delayed = true`.

The quote-age control (`max_quote_age_seconds = 120`) measures how long
ago **we fetched** the quote, not how old the market data inside it is. A
quote fetched three seconds ago can describe the market as it was fifteen
minutes earlier and will pass that check.

So today's fills exercise the machinery and do not measure the strategy.
Options and the decision required: `docs/progress/DATA-FEED-ENTITLEMENT.md`.

## Company intelligence, continued

Peer comparison was at the edge of the 90-second API budget. Profiled
before changing anything:

| | before | after |
|---|---|---|
| Cold GIS peer comparison | 88.4 s | ~21 s |
| Downloaded | 112.7 MB | 56 MB |
| Immutable writes | 19,748 | ~26 per company |
| Warm repeat | 16.8 s | 2.9 s |

What the time was actually going on: 19,748 `put_item` calls persisting
every XBRL observation that nothing ever read; each company's 4.5 MB
taxonomy downloaded twice, once only to read a share count (the
`companyconcept` endpoint returns it in ~10 KB); and 58 sequential HTTP
round trips in candidate profiling, now bounded-concurrent at 9 with
every store write still on the calling thread.

Live validation across symbol types found three further defects:

- **COST and GE read IRREGULAR** though both pay quarterly. Cadence was
  judged on `max(gap) - min(gap)`, so two odd intervals out of 37 were
  enough. Judged on the majority now; both read ACTIVE.
- **`next_ex_date` was always None** for every company: the
  corporate-action window ended today, and an announced future ex-date
  cannot be inside it. The window reaches 120 days ahead now. (AAPL still
  shows none — it has not declared its November dividend yet, which is
  the honest answer.)
- **Re-ingesting AAPL reported all 41 actions as conflicting.** The
  request window sat inside each action's provenance, so changing the
  window changed every row. Immutability compares the fact now, not the
  circumstances of fetching it; a changed amount is still a conflict.
  Verified live: conflicts 41 → 0.

Validated live: AAPL (ACTIVE, 4-for-1 2020 split), NVDA (ACTIVE, 10-for-1
2024 and 4-for-1 2021), TSLA (NO_DIVIDEND, two forward splits), GE
(ACTIVE, **1-for-8 reverse split 2021** labelled with direction in
words), COST (ACTIVE with two special distributions kept out of the
regular series), GIS (full profile, fundamentals, peers, comparison).

GIS peer comparison excludes HSY, KDP, CPB and MDLZ as `PERIOD_MISMATCH`:
GIS's fiscal year ends in May, theirs in December or August. That is the
silent-fiscal-mismatch control working on live data, and it is why only
one or two peers contribute to each metric.

## The harness could not catch any of it

`scripts/falsifying_controls.py` ran a hand-maintained list of 18 test
modules. The company-intelligence and autonomy suites were not on it, so
all 15 new mutations "survived" — not because the guards were weak but
because the tests that catch them were never run. The 19A autonomy work
had never been mutation-tested either, apart from `test_readiness`.

It discovers `tests/` now, so a new test file participates as soon as it
exists. A harness that reports coverage it does not have is worse than no
harness, because the report reads like evidence.
